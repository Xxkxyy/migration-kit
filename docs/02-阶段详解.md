# 02 · 阶段详解（可直接照做）

> 每节固定四段：**目标 → 操作 → 验收 → 失败处理**。
> 所有命令默认在目标端执行，标注 `[源端]` 的除外。

---

## 阶段 0 · 勘查

### 目标
确认"能不能搬"，把不确定项提前清零。

### 操作

**0.1 连通性**
```bash
# 目标端 → 源端（双向都要测）
for ip in 10.0.0.221 10.0.0.222 10.0.0.223 10.0.0.224 10.0.0.225; do
  timeout 3 bash -c "echo > /dev/tcp/$ip/22" && echo "$ip SSH OK" || echo "$ip SSH FAIL"
done
```

**0.2 是否同二层（决定能不能换 IP）**
```bash
# 在 51 网段的机器上临时挂一个 50 网段地址，看能否 ARP 到对端网关
ip addr add 10.0.0.250/24 dev ens7
ping -c2 -W2 -I 10.0.0.250 10.0.0.254
ip neigh show 10.0.0.254      # 必须是 REACHABLE，不能是 INCOMPLETE/FAILED
ip addr del 10.0.0.250/24 dev ens7
```
> 判据：ARP 解析成功 = 同一广播域，可直接换 IP；`INCOMPLETE` = 不同 VLAN，必须改客户端或在防火墙上做 DNAT。

**0.3 凭据矩阵**
逐台记录"IP / 用户 / 口令 / 是否可 sudo"，口令含特殊字符（`!`、`@`）时注意：
- PowerShell 里单引号包裹
- SSH 自动化必须用半角字符（全角标点会导致认证必然失败）

### 验收
`inventory/00-connectivity.md` 里 5 台源机 + 5 台目标机全部 ✅。

### 失败处理
- SSH 不通：先查防火墙（`firewall-cmd --list-all`）、再查 `sshd` 白名单
- 口令不对：确认是否全角字符、是否有 `!` 被 shell 转义

### 目标

## 阶段 2 · 目标环境与镜像

### 目标
目标端具备与源端等价（或更高）的运行时，镜像 ID 完全一致。

### 操作

**2.1 系统准备**
```bash
# 关闭 SELinux 干扰（或设 permissive）
setenforce 0; sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config

# 时间同步
timedatectl set-timezone Asia/Shanghai
chronyc makestep || ntpdate -u <ntp-server>

# 数据盘（如多块盘需合并）
pvcreate /dev/vdb /dev/vdc
vgcreate vg_data /dev/vdb /dev/vdc
lvcreate -l 100%FREE -n lv_data vg_data
mkfs.xfs /dev/vg_data/lv_data
mount /dev/vg_data/lv_data /data
echo '/dev/vg_data/lv_data /data xfs defaults 0 0' >> /etc/fstab
```

**2.2 Docker**
```bash
dnf install -y docker-ce docker-ce-cli containerd.io
systemctl enable --now docker
docker info | grep -E 'Server Version|Storage Driver'
```

**2.3 镜像搬运**
```bash
[源端] docker save one/java:8 | pigz -1 > /tmp/one-java8.tgz
       # 大镜像用 pigz 并行压缩，1 Gbps 网卡下可省 40% 时间
[传输] scp /tmp/one-java8.tgz root@<新机>:/tmp/
[目标] docker load < /tmp/one-java8.tgz
```

**2.4 校验**
```bash
# 两侧 IMAGE ID 必须一致
docker images --format '{{.Repository}}:{{.Tag}} {{.ID}}' | sort > /tmp/a
# 逐条 diff
```

### 验收
镜像数一致、每个 IMAGE ID 一致、`docker run --rm <image> java -version` 可执行。

### 失败处理
- `docker load` 报 layer 损坏 → 重新 `save`，不要用 `--output` 到 NFS
- 目标端磁盘不足 → 先 `docker system prune -a`，镜像目录迁到 `/data`

## 阶段 3 · 文件数据搬运

### 目标
应用目录、附件、日志（按需）逐字节一致，且**可分批重跑**。

### 操作

**3.1 先看规模与差异**
```bash
rsync -a --numeric-ids --dry-run --stats \
  -e 'ssh -o StrictHostKeyChecking=no' \
  root@<源端>:/data/app/docker-scloud/ /data/app/docker-scloud/
```
只看两项：`Number of files`、`Total transferred file size`。

**3.2 实跑（分批 + 断点续传）**
```bash
python scripts/03_rsync_sync.py --apply --batch 2000
```
脚本要点：
- `-a --numeric-ids`（保留属主/权限/时间）
- **不加 `--delete`**（源端日志轮转会导致误删）
- 失败自动重试 3 次，每次间隔递增
- 每批结束后立即统计"文件数 + 字节总和"

**3.3 校验（关键）**
```bash
# 两侧各跑一次，数字必须完全相同
find /data/app/docker-scloud -type f | wc -l
find /data/app/docker-scloud -type f -printf '%s\n' | awk '{s+=$1} END {print s}'
```

### 验收
文件数、字节总和两侧完全一致；差异只允许是"源端轮转产生的日志文件"，需逐条列明。

### 失败处理
| 现象 | 原因 | 处置 |
|---|---|---|
| 差异文件数固定不变 | 源端在写日志 | 记录文件名，切流前最后补一次 |
| 传输中断 | 网络抖动 | 直接重跑，rsync 天然幂等 |
| 属主丢失 | 未加 `--numeric-ids` | 加参数重跑 |

## 阶段 4 · 数据库建模

### 目标
目标库的"骨架"（库、表、视图、例程、触发器、账号）与源端一致。

### 操作

**4.1 建库（字符集按源端）**
```sql
SELECT schema_name, default_character_set_name, default_collation_name
FROM information_schema.schemata
WHERE schema_name NOT IN ('mysql','sys','information_schema','performance_schema');
```
```sql
CREATE DATABASE `ek_patient` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```
> 注意：SQL 里的反引号在 shell 里会被当命令替换，**必须写成 SQL 文件再执行**，不要内联。

**4.2 表结构**
```bash
mysqldump -uroot -p --no-data --routines=false --triggers=false \
  --single-transaction --set-gtid-purged=OFF <db> > /tmp/<db>-schema.sql
```

**4.3 视图 / 例程 / 触发器**
```bash
mysqldump -uroot -p --no-create-info --no-data --routines --triggers --skip-triggers=false <db> > /tmp/<db>-objects.sql
```

**4.4 账号（注意主机段）**
```sql
SELECT user, host FROM mysql.user WHERE host NOT IN ('localhost','127.0.0.1');
SHOW GRANTS FOR 'newhis'@'10.0.0.%';
```
重放时把 `10.0.0.%` 改成新网段 `10.1.0.%`；`GRANT` 用 `IDENTIFIED BY PASSWORD '<hash>'` 保留原口令哈希。

### 验收
```sql
-- 两端口径一致
SELECT (SELECT COUNT(*) FROM information_schema.tables WHERE table_schema NOT IN (...)) AS tables,
       (SELECT COUNT(*) FROM information_schema.views ...) AS views,
       (SELECT COUNT(*) FROM information_schema.routines ...) AS routines;
```

### 失败处理
- 视图创建失败：检查 `DEFINER` 账号是否已存在（先建账号再建视图）
- 例程报 `1418`：`log_bin_trust_function_creators=1`

## 阶段 5 · 数据灌入（核心难点）

### 目标
在可接受时间内把 TB 级数据灌完，且**执行计划正确**。

### 操作

**5.1 导入期参数**（见 `config/my.cnf.import`）
```ini
innodb_flush_log_at_trx_commit=0
innodb_doublewrite=0
innodb_flush_method=O_DIRECT_NO_FSYNC
innodb_change_buffering=none
skip-log-bin
innodb_stats_auto_recalc=OFF   # 导入期关掉，切生产必须打开！
```
重启后确认：`SELECT @@innodb_flush_method, @@innodb_doublewrite, @@innodb_flush_log_at_trx_commit;`

**5.2 分档策略**

| 档位 | 判定 | 并发 | 备注 |
|---|---|---|---|
| 小表 | `data_length < 100MB` | 1 | 直接 dump/load |
| 中表 | `100MB ~ 5GB` | 4 | 按表切分 |
| 大表 | `> 5GB` 或 `rows > 1000万` | 8 | 按 PRIMARY 区间切片 |

**5.3 大表流程（脚本 `04_mysql_bulkload.py` 已实现）**

```
① 源端取边界:  SELECT MIN(id), MAX(id) FROM db.tb
② 目标端:      TRUNCATE TABLE db.tb
③ DROP 二级索引（保留 PRIMARY）——导入期间不为索引付出随机写代价
④ 切 N 段，每段:
     mysqldump --where="id >= A AND id <= B" --no-create-info --skip-add-locks ...
        | mysql db
     远端写 rc 文件（0/非0）
⑤ 轮询 rc，全部为 0 才算完成；非 0 的段单独重跑
⑥ ADD INDEX 重建二级索引
⑦ ANALYZE TABLE 重算统计
⑧ 与源端 COUNT(*) 比对
```

**5.4 幂等与互斥**
- 脚本入口 `flock -n 9`，防止被重复启动（曾发生两次实例互相 TRUNCATE 同一张表）
- 重试走 `--insert-ignore`，避免主键冲突导致整段失败
- **禁止**用 `DELETE` 做区间清理：带 LONGTEXT 的行逐行删，慢盘上 26 分钟零吞吐还会回滚 40 分钟

**5.5 切回生产参数**
```bash
sed -i \
 -e 's/^innodb_flush_log_at_trx_commit=0/innodb_flush_log_at_trx_commit=2/' \
 -e 's/^innodb_doublewrite=0/innodb_doublewrite=1/' \
 -e 's/^innodb_stats_auto_recalc=OFF/innodb_stats_auto_recalc=ON/' \
 -e 's/^skip-log-bin/log_bin=\/data\/mysql\/binlog\/mysql-bin/' \
 /etc/my.cnf
systemctl restart mysqld
```

### 验收
1. 每个分片 `rc=0`
2. 大表 `COUNT(*)` 两侧相等（本次：SignData 18,525,216；External 7,526,639）
3. **`mysql.innodb_table_stats` 里"非空表但 n_rows=0"的数量 = 0**
```sql
SELECT COUNT(*) FROM mysql.innodb_table_stats s
JOIN information_schema.tables t
  ON t.table_schema=s.database_name AND t.table_name=s.table_name
WHERE s.n_rows=0 AND t.data_length>20000
  AND s.database_name NOT IN ('mysql','sys');
```

### 失败处理
| 现象 | 根因 | 处置 |
|---|---|---|
| 导入 100~200 行/秒 | 每次提交 fsync，慢盘 1.3 IOPS | 改 `flush=0` + `O_DIRECT_NO_FSYNC` + 索引后建 |
| 分段 RC=0 但 0 行 | 边界在 TRUNCATE 之后取，MIN/MAX 为 NULL | 边界必须从**源端**取 |
| 重试立刻主键冲突 | 分段不幂等 | 改 `--insert-ignore` |
| 表体积膨胀 10 倍+ | 反复 `INSERT IGNORE` 叠加 | 改"TRUNCATE + 单次分段"，禁止叠加 |
| 业务查询 90 秒 / 网关 504 | 统计全 0，优化器以为表空 | `ANALYZE` + `auto_recalc=ON` |

## 阶段 6 · 应用重建

### 目标
不靠记忆手写 `docker run`，而是**从源端容器定义还原**。

### 操作

**6.1 导出定义（源端）**
```bash
docker inspect <name> > /tmp/<name>.json
```

**6.2 生成启动命令（`05_rebuild_containers.py`）**

从 `docker inspect` 提取：Image / Cmd / Env / Binds / PortBindings / WorkingDir / HostConfig.Memory / RestartPolicy / NetworkMode。

三个必须处理的细节：

| 细节 | 错误做法 | 正确做法 |
|---|---|---|
| Entrypoint + Cmd | 两段都拼 → `java java -jar` / `weed weed server` | 镜像自带 ENTRYPOINT 时**只传 Cmd** |
| 命令里的旧 IP | 只改 env，忘了 Cmd 参数 | 对 Cmd 逐项做 IP 替换 |
| 挂载路径 | 按 compose 里的相对路径猜 | 用 `docker inspect` 里的绝对路径，逐条 `ls` 确认真实数据 |

**6.3 启动顺序**
```
nacos → redis → rabbitmq → gateway → authserver/sys/oss → 业务服务 → 前端 nginx
```
每起一个等服务注册成功（或端口监听）再起下一个。

**6.4 中间件常见坑**
- RabbitMQ 3.6：`guest` 仅 localhost 可登录；业务账号/ vhost 必须显式建
- RabbitMQ 数据目录：确认挂载的是**真正有 mnesia 的那个目录**，挂空目录会变成全新节点
- Nacos：`namespace` 与源端一致，否则服务注册到默认命名空间

### 验收
```bash
docker ps -a --format '{{.Names}}\t{{.Status}}' | grep -v '^.*Up' | wc -l   # 必须 0
curl -s 'http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=100&namespaceId=<ns>'
```

### 失败处理
| 现象 | 根因 | 处置 |
|---|---|---|
| 容器启动即退出 | 命令拼接错误 | `docker logs` 看首行，比对 inspect 的 Entrypoint/Cmd |
| 服务注册不上 | namespace/地址错 | 查 `bootstrap*.properties` 与容器 env |
| 服务起来但业务 502 | 上游未启动 | 按依赖顺序补齐 |

## 阶段 7 · 配置改指

### 目标
目标端配置文件里**不留任何旧网段地址**。

### 操作

**7.1 先摸清范围**
```bash
grep -rlI '10\.0\.0\.' /data/app /opt /etc \
  --exclude-dir=mysql --exclude='*.log' | wc -l
```
> 坑：`--exclude-dir=data` 会把整个业务目录排掉，统计结果永远是 0。要么不排除，要么精确到子目录。

**7.2 批量替换（保留 .bak_ip）**
```bash
python scripts/06_repoint_configs.py --apply \
  --old 10.0.0. --new 10.1.0. \
  --roots /data/app /opt /etc
```
脚本行为：备份为 `<file>.bak_ip`（已存在则跳过，保留**最原始**那份）→ 原地替换 → 输出改动清单。

**7.3 容器环境变量**
`docker inspect` 里的 Env 不会随文件改，必须重建容器（阶段 6 重跑）。

**7.4 数据库授权**
```sql
UPDATE mysql.user SET host='10.1.0.%' WHERE host='10.0.0.%';
FLUSH PRIVILEGES;
```
> 更稳的做法：`RENAME USER 'u'@'old' TO 'u'@'new'`，避免直接改系统表。

### 验收
```bash
grep -rlI '10\.0\.0\.' /data/app /opt /etc --exclude='*.bak_ip' --exclude-dir=mysql
# 输出必须为空
```

### 失败处理
- 改完服务连不上：检查是否漏了容器 Env（需重建容器）
- 页面出现旧 IP 的静态资源地址：多半存在数据库里，按表搜 `LIKE '%10.0.0.%'` 处理

## 阶段 8 · 端到端验收

### 目标
证明"用户点得动"，而不是"进程活着"。

### 操作

**8.1 四层验证**

```bash
# ① 进程层
docker ps --format '{{.Names}} {{.Status}}' | grep -c Up

# ② 注册层
curl -s 'http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=100&namespaceId=<ns>'

# ③ 接口层（从外部经 nginx）
curl -i 'http://<新IP>:<nginx端口>/authserver/oauth/token'
#   期望: HTTP/1.1 401 + serial 头 + {"exception":"未认证，请先登录"}
#   若 502/504: 网关后面还有服务没起或很慢

# ④ 数据层（抽样）
SELECT COUNT(*) FROM <大表> WHERE id = <源端抽出的主键>;
```

**8.2 性能基线（容易被忽略，但必须做）**

```sql
-- 打开慢日志
SET GLOBAL slow_query_log=ON;
SET GLOBAL long_query_time=1;
SET GLOBAL log_output='TABLE';

-- 看排名
SELECT ROUND(query_time) sec, rows_sent, rows_examined,
       LEFT(REPLACE(sql_text,'\n',' '),120)
FROM mysql.slow_log ORDER BY query_time DESC LIMIT 20;
```

对 TopN 慢查询做 `EXPLAIN`，判断：
- `type=ALL` 且 `rows` 接近表行数 → **缺索引**，按 WHERE 列顺序建联合索引
- `rows` 很小但 `query_time` 很大 → **IO 瓶颈**，看是否需要预热/扩容

### 验收
四层全绿 + 慢查询 Top20 里没有"全表扫描级"的条目。

### 失败处理
见 `03-排障与坑位.md`。

## 阶段 9 · 切流

### 前置
1. 阶段 8 全绿
2. 有明确停机窗口（本次约 20 分钟）
3. 回退演练过一次（起旧容器 → 验证 → 再停）

### 操作
```bash
# 1) 停旧容器（只 stop，不 rm）
docker stop -t 30 $(docker ps -q)

# 2) 最后一次增量（只传停写后的差异）
rsync -a --numeric-ids root@<源端>:/data/app/... /data/app/...

# 3) 冒烟
curl -i http://<新IP>:<port>/authserver/oauth/token

# 4) 客户端/域名切到新地址

# 5) 旧机保留，不销毁
```

### 回退
```bash
docker start $(docker ps -aq)   # 旧机
```
回退时间 < 5 分钟，数据以旧机为准（新机期间写入需另行评估）。

### 观察期
1~2 周。观察项：错误率、慢查询数、磁盘增长、内存/句柄。
