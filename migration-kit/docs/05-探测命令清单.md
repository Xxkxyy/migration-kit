# 05 · 探测命令清单（逐条说明看什么）

> 全部命令都在 `scripts/lib/probe.sh` 里，按段分组，可直接 `bash probe.sh <段名>`。
> 这里给的是**按阶段该跑哪些、看哪几个数字**。

---

## 一、连通与凭据（阶段 0）

```bash
# 1. TCP 是否可达（区分网络不通 vs 认证失败）
timeout 3 bash -c "echo > /dev/tcp/10.0.0.221/22" && echo OK

# 2. SSH 认证（注意口令里的全角字符，！!= !）
ssh -o StrictHostKeyChecking=no root@10.0.0.221 'hostname; uname -r'

# 3. 是否同二层（决定能否直接换 IP）★ 最容易误判
ip addr add 10.0.0.250/24 dev ens7
ping -c2 -W2 -I 10.0.0.250 10.0.0.254
ip neigh show 10.0.0.254          # REACHABLE=同二层；INCOMPLETE/FAILED=不同 VLAN
ip addr del 10.0.0.250/24 dev ens7

# 4. 两侧网关是否同一台设备
ip neigh | grep '\.254 '           # 比 MAC：相同=同一台 L3 设备
```

| 看什么 | 判据 |
|---|---|
| `/dev/tcp` 结果 | 不通 → 先查防火墙、网段、ACL |
| `ip neigh` 状态 | `INCOMPLETE` 就**不要**尝试换 IP |
| 口令 | 含 `！＠＃` 等全角标点必须转半角，否则认证必然失败 |

## 二、系统与存储（阶段 1，决定导入策略）

```bash
# 系统画像
cat /etc/os-release | head -3
uname -r; nproc; free -g; date '+%Z %z'; getenforce
bash -c 'ulimit -n; ulimit -u'
cat /proc/sys/vm/swappiness

# 磁盘
df -hT | grep -vE 'tmpfs|overlay'
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
findmnt -no SOURCE,TARGET,FSTYPE,OPTIONS /data
du -sh /data/*/ | sort -h | tail -10

# ★ 4K 同步写 IOPS —— 迁移里最关键的单一指标
dd if=/dev/zero of=/tmp/io bs=4k count=500 oflag=direct,dsync

# 顺序读写
dd if=/dev/zero of=/tmp/seq bs=1M count=1024 oflag=direct
dd if=/data/app/x.jar of=/dev/null bs=1M count=512 iflag=direct

# IO 调度器（虚拟盘通常是 none/mq-deadline，别设 cfq）
cat /sys/block/sdb/queue/scheduler
```

| 看什么 | 判据 | 动作 |
|---|---|---|
| 4K 同步写结果 | 500 次若耗时 > 100s（<5 IOPS） | 必须用导入期参数；考虑换盘 |
| `df` 目标分区 | 目标容量 ≥ 源端 × 1.3 | 不足先做 LVM 合并 |
| `du -sh /data/*` | 找出真正的大头 | 决定 rsync 分批顺序 |
| swappiness | > 30 建议调到 10 | 避免大 buffer pool 被换出 |

## 三、Docker 资产（阶段 1/6）

```bash
docker version --format '{{.Server.Version}}'
docker info --format 'driver={{.Driver}} root={{.DockerRootDir}}'

# 镜像（比对 IMAGE ID，不是 tag）
docker images --format '{{.Repository}}:{{.Tag}}|{{.ID}}|{{.Size}}'
docker save <img> | gzip -1 > /tmp/i.tgz     # 源端导出
docker load < /tmp/i.tgz                     # 目标端导入

# 容器清单（这四个字段决定能否完整重建）
docker ps -a --format '{{.Names}}|{{.Image}}|{{.Status}}|{{.Ports}}'
docker inspect <name> --format 'EP={{.Config.Entrypoint}} CMD={{.Config.Cmd}}'
docker inspect <name> --format '{{range .Mounts}}{{.Source}} => {{.Destination}}{{"\n"}}{{end}}'
docker inspect <name> --format '{{range .Config.Env}}{{println .}}{{end}}'
docker inspect <name> --format '{{.HostConfig.RestartPolicy.Name}} {{.HostConfig.NetworkMode}}'

# 端口真实映射（firewalld 要按这个开，不是按 EXPOSE）
docker ps --format '{{.Names}} {{.Ports}}'

# 网络与卷
docker network ls
docker volume ls -q
docker system df
```

| 看什么 | 坑 |
|---|---|
| `Entrypoint` + `Cmd` | 两者只能拼一次，否则 `weed weed server` / `java java -jar` |
| `Mounts` 的 Source | 必须是**真有数据**的绝对路径（挂错空目录＝新节点） |
| `Env` | 地址类变量不随配置文件改动，必须重建容器 |
| `Ports` 的 HostPort | 与 EXPOSE 不同，防火墙按 HostPort 开 |

## 四、MySQL 资产与健康（阶段 1/4/5/8）

```bash
# 版本与关键参数
mysql -uroot -N -e "select version(), @@version_comment"
mysql -uroot -N -e "select @@datadir, @@character_set_server, @@lower_case_table_names,
   @@innodb_buffer_pool_size/1024/1024/1024 bp_gb, @@innodb_flush_log_at_trx_commit flush,
   @@innodb_doublewrite dw, @@innodb_flush_method, @@log_bin, @@sync_binlog,
   @@innodb_stats_auto_recalc stats_recalc"

# 运行状态（导入前后对比）
mysql -uroot -e "show global status where Variable_name in
  ('Threads_connected','Max_used_connections','Aborted_connects','Aborted_clients',
   'Innodb_buffer_pool_reads','Innodb_buffer_pool_read_requests','Uptime')"

# 库/表/对象规模（★ 不要相信 table_rows，只用来排序）
mysql -uroot -e "select table_schema, count(*) tables,
  round(sum(data_length+index_length)/1024/1024/1024,2) gb
  from information_schema.tables where table_schema not in
  ('mysql','sys','information_schema','performance_schema') group by 1 order by gb desc"

# 真实行数（大表也要跑，这是唯一可信的证据）
mysql -uroot -N -e "select count(*) from ek_patient.T_NurseDataDetail"

# 磁盘实际占用（比 data_length 准）
du -sh /data/mysql/data/ek_patient

# 对象数量口径
mysql -uroot -N -e "select
 (select count(*) from information_schema.tables where table_schema not in (...)) tables,
 (select count(*) from information_schema.views where table_schema not in (...)) views,
 (select count(*) from information_schema.routines ...) routines,
 (select count(*) from information_schema.triggers ...) triggers"

# 账号与授权主机段（换网段必须改）
mysql -uroot -e "select user, host from mysql.user where host not in ('localhost','127.0.0.1')"
mysql -uroot -N -e "show grants for 'newhis'@'10.0.0.%'"

# 索引指纹（迁移前后 diff，漏一个索引=业务慢百倍）
mysql -uroot -N -e "select table_schema, table_name, index_name, seq_in_index, column_name
  from information_schema.statistics where table_schema not in (...) order by 1,2,3,4"

# ★ 统计信息体检（迁移后必查）
mysql -uroot -N -e "select count(*) from mysql.innodb_table_stats s
  join information_schema.tables t on t.table_schema=s.database_name
   and t.table_name=s.table_name
  where s.n_rows=0 and t.data_length>20000 and s.database_name not in ('mysql','sys')"

# 长查询 / 锁等待
mysql -uroot -e "select id, user, host, db, time, state, left(info,60)
  from information_schema.processlist where command<>'Sleep' order by time desc limit 10"

# 慢日志
mysql -uroot -e "set global slow_query_log=on; set global long_query_time=1;
                 set global log_output='TABLE'"
mysql -uroot -e "select round(query_time) sec, rows_sent, rows_examined,
  left(replace(sql_text,'\n',' '),120) from mysql.slow_log order by query_time desc limit 10"

# 错误日志
tail -n 50 /data/mysql/*.err | grep -aE 'ERROR|Aborted|denied'
```

| 看什么 | 判据 |
|---|---|
| `table_rows` | **不可信**（本次实测偏差 2~17 倍），只用它的排序 |
| `data_length` | 也来自统计，导入后可能为 0 |
| `n_rows=0 且 data_length>20000` | 统计失效，必须 ANALYZE |
| `Innodb_buffer_pool_reads/read_requests` | 比值 > 0.01 说明 buffer pool 不够 |
| 慢日志 `rows_examined` ≫ `rows_sent` | 索引问题 |

## 五、应用与中间件（阶段 1/6/8）

```bash
# 应用目录与大小
ls -la /data/app; du -sh /data/app/*/*/ | sort -h | tail

# compose 与实际容器是否一致（经常不一致）
ls -l /data/app/*/docker-compose.y*ml

# jar 清单（版本核对）
find /data/app -maxdepth 5 -name '*.jar' -printf '%s %p\n' | sort -rn | head -15

# 写死 IP 的配置（改指范围）
grep -rlIE '([0-9]{1,3}\.){3}[0-9]{1,3}' /data/app/$SVC \
  --exclude='*.jar' --exclude='*.log' --exclude-dir=logs --exclude='*.bak*'

# Redis
docker exec redis redis-cli info server | head -8
docker exec redis redis-cli dbsize

# RabbitMQ（vhost / 账号是必查项）
docker exec rabbitmq rabbitmqctl list_vhosts
docker exec rabbitmq rabbitmqctl list_users
docker exec rabbitmq rabbitmqctl list_permissions -p scloud-release

# Nacos 注册情况
curl -s 'http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=100&namespaceId=<ns>'

# SeaweedFS 集群
curl -s 'http://127.0.0.1:9333/cluster/status'
curl -s 'http://127.0.0.1:9333/dir/status?pretty=y'

# 业务日志里的报错（按签名归类，不要只看第一行）
docker logs --since 30m <container> 2>&1 | grep -aE 'ERROR|Exception' | tail -20
```

| 看什么 | 坑 |
|---|---|
| `list_vhosts` | vhost 丢了 → 所有 MQ 消费者 `ACCESS_REFUSED` |
| `list_users` | 业务用的是 `newhis/newhis`，不是 `guest` |
| Nacos 服务数 | 少一个就是某个服务没起来 |
| 容器日志 | 优先看**第一条** ERROR（后面都是级联） |

## 六、验收命令（阶段 8）

```bash
# ① 进程层
docker ps -q | wc -l
docker ps -a --format '{{.Status}}' | grep -vc '^Up'      # 必须 0

# ② 注册层
curl -s 'http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=100&namespaceId=<ns>'

# ③ 接口层（拿到应用自己的业务响应才算通）
curl -i 'http://<新IP>:4431/authserver/oauth/token'
#   期望: 401 + serial 头 + {"exception":"未认证，请先登录"}
#   502/504: 网关后面还有服务没起

# ④ 数据层
mysql -uroot -N -e "select count(*) from <大表> where id = <源端抽样的主键>"

# ⑤ 文件层
find /data/app/... -type f | wc -l
find /data/app/... -type f -printf '%s\n' | awk '{s+=$1} END{print s}'
```

## 七、按阶段速查表

| 阶段 | 必跑命令 | 过关数字 |
|---|---|---|
| 0 勘查 | `/dev/tcp`、`ip neigh` | 10/10 通，ARP REACHABLE |
| 1 盘点 | probe.sh 全段 | 每个容器有 EP/CMD/Mounts/Env |
| 2 镜像 | `docker images --format ... {{.ID}}` | 两侧 IMAGE ID 全等 |
| 3 文件 | `find | wc -l` + 字节总和 | 两侧完全相等 |
| 4 建模 | 对象数量 + 索引指纹 + 账号 | 差异 0 |
| 5 灌数 | `COUNT(*)`、统计体检 | 行数相等，n_rows=0 的非空表 = 0 |
| 6 应用 | `docker ps -a`、Nacos 列表 | 非 Up=0，服务数达标 |
| 7 改指 | `grep -rl 旧网段` | 命中 0 |
| 8 验收 | curl 401、慢日志 TopN | 无 5xx，无全表扫描 |
| 9 切流 | `--precheck` | 全绿才切 |
